# SIH 2026 Internal Hackathon – Team Repository Instructions

## 1. Purpose

This repository is the **official submission repository template** for the Smart India Hackathon (SIH) 2026 Internal Hackathon.

Each **Team Leader** is responsible for creating and maintaining the team's repository by following the instructions below.

> **Important:** Only the Team Leader should perform the repository setup and ensure that all required information and files are uploaded correctly.

## 2. Step 1 – Fork This Repository

1. Click **Fork**.
2. Select your GitHub account as the destination.
3. Create the forked repository under your GitHub account.

Do **not** create a new repository from scratch. The repository must be created by **forking the official repository**.

---

## 3. Step 2 – Rename the Repository

After successfully forking the repository:

1. Open your forked repository.
2. Go to **Settings → General**.
3. Locate the **Repository name** field.
4. Rename the repository using the **Team Number assigned to your team**.

> **Do not use your team name, problem statement title, college name, or Team Leader's name as the repository name.**

The repository name must exactly match the **Team Number provided in the official team list**.

## 4. Step 3 – Verify Your Team Number

The official list containing the **Team Numbers and corresponding team details** is available through the link provided by the SIH Internal Hackathon coordination team.

Before uploading any information:

* Verify your **Team Number**.
* Verify your **Problem Statement**.
* Verify the **Team Members**.
* Verify the **Mentor details**.

If there is any discrepancy, contact the SIH Internal Hackathon coordination team before making the final submission.

* Mentor details

# 6. Step 5 – Add Mentor Details

Provide the details of the faculty mentor assigned to your team.

| Mentor Name | Designation | Department | Official Email ID |
| ----------- | ----------- | ---------- | ----------------- |
|             |             |            |                   |

Ensure that the mentor details are accurate and match the information provided by the SIH coordination team.

# 7. Step 6 – Add Problem Statement Details

The selected problem statement must be clearly documented.

Provide:

* **Problem Statement ID**
* **Problem Statement Title**
* **Problem Statement Description** (if required)
* **Theme / Category**
* **Ministry / Organization**, wherever applicable

Example:

```text
Problem Statement ID : SIHXXXX
Problem Statement    : <Problem Statement Title>
Theme                : <Theme>
Organization         : <Ministry / Organization>
```

The Problem Statement ID and title must exactly match the officially assigned/selected problem statement.


# 8. Step 7 – Upload Files to the `share` Folder

All files that need to be submitted/shared with the SIH Internal Hackathon coordination team must be placed inside the following folder:

```text
share/
```

The `share` folder must contain **only the required submission documents**.

## Required Files

### 8.1 Team Presentation

Upload the final presentation prepared by your team.

Recommended filename:

```text
TEAM-XX_Presentation.pptx
```

or

```text
TEAM-XX_Presentation.pdf
```

The presentation should be the **final version presented during the Internal Hackathon**.


### 8.2 Student Declaration

Upload the completed **Student Declaration Format** provided by the SIH Internal Hackathon coordination team.

Recommended filename:

```text
TEAM-XX_Student_Declaration.pdf
```

If the declaration format is provided as a Word document and the organizers specifically require the editable version, upload the required format accordingly.


# 9. Step 7 – Commit and Push Changes

After updating the information and uploading the required documents:

1. Review all changes.
2. Commit the changes to your repository.
3. Push the changes to GitHub.
4. Open the repository in a browser and verify that all files are visible.

Use meaningful commit messages such as:

```text
Added team details and mentor information
```

and

```text
Uploaded presentation and student declaration
```

# 11. Important Rules

### Repository Name

The repository name **must be the assigned Team Number**.

```text
Correct   : TEAM-07
Incorrect : Team7
Incorrect : SIH-Team-07
Incorrect : SmartWasteManagement
Incorrect : Team_Ramaguru
```

### File Location

The presentation and student declaration **must be placed inside**:

```text
share/
```

### Accuracy

All submitted information must exactly match the official SIH Internal Hackathon team records.

### Final Submission

The Team Leader is responsible for ensuring that the repository is complete, correctly structured, and accessible before the submission deadline.

---

# 12. Submission

Once the repository has been completely updated and verified, submit the **GitHub repository URL** through the official submission link provided by the SIH Internal Hackathon coordination team.

### Repository URL Format

```text
https://github.com/<your-github-username>/TEAM-XX
```

Replace `TEAM-XX` with your actual assigned Team Number.

---

## 13. Responsibility of the Team Leader

The Team Leader is the **single point of responsibility** for the team's GitHub repository.

The Team Leader must ensure that:

1. The repository is correctly forked and renamed.
2. All team information is accurate.
3. Mentor information is included.
4. The selected problem statement is correctly documented.
5. The final presentation is uploaded.
6. The Student Declaration is uploaded.
7. The repository is updated before the deadline.
8. The final repository link is submitted through the official submission mechanism.

> **Please complete the repository setup and upload all required documents well before the Internal Hackathon submission deadline to avoid last-minute issues.**
